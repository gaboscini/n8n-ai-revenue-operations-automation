# Demonstration guide

## Recommended walkthrough

1. Open the full workflow screenshot and explain the seven color-coded modules.
2. Start with the lead gateway and show validation, idempotency, and safe website research.
3. Compare the qualification output with the independent evaluator and human-review branch.
4. Show that deterministic code—not AI—sets the score, tier, owner, and SLA.
5. Follow the native HubSpot, Supabase, Gmail-draft, and Slack paths.
6. Explain how reply and booking events stop scheduled follow-up.
7. Show discovery analysis, contradictions, proposal blockers, and the CRM record.
8. Walk through the scheduler, SLA monitor, and weekly executive report.
9. Finish with the shared dead-letter path and operator-controlled replay package.

## Suggested interview narrative

The project is intentionally larger than a linear lead-capture automation. It demonstrates how to separate model analysis from business policy, preserve state across independent events, use native integration nodes, create human checkpoints, and design operational recovery into the same automation.

## Portfolio positioning

Describe the project as a tested, end-to-end portfolio implementation that uses non-production configuration and synthetic business data. Explain that adopters must connect their own n8n credentials and account-specific identifiers. Do not describe it as a hosted service, a customer deployment, or a production-load certification unless separate evidence is available.
